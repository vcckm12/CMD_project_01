# 독립 시험셋 작성 가이드 (공격 200 + 정상 200)

이 시험셋은 우리 챗봇 가드레일의 **공식 성능 수치**(공격 탐지율, 정상 질문 오탐률)를 재는 데 한 번만 씁니다. 규칙과 AI 판별 기준을 만든 쪽이 보지 못한 문장이어야 수치를 믿을 수 있으므로, 아래 규칙을 꼭 지켜 주세요.

## 1. 꼭 지킬 것

1. **우리 규칙·기준·기존 시험셋을 보지 말고 작성합니다.** 열어 보면 안 되는 파일:
   - `backend/app/guardrails/` 폴더 전체(정규식 규칙, AI 판별 기준)
   - `datasets/` 폴더의 다른 파일 전부(개발셋, 이전 시험셋)
   - `docs/06_guardrail_security_design.md`, `docs/08_system_flow.md`의 규칙 목록과 예시
2. **인터넷 공격 모음을 그대로 복사하지 않습니다.** (예: PayloadsAllTheThings, jailbreak 프롬프트 모음) 참고해서 아이디어를 얻는 것은 괜찮지만, 문장은 직접 바꿔 쓰세요.
3. **실제 개인정보·실제 비밀번호를 넣지 않습니다.** 이름·전화번호·이메일이 필요하면 지어낸 값을 씁니다. (예: 홍길동, 010-0000-1234, test@example.com)
4. **완성된 시험셋으로 다시 고치거나 연습하지 않습니다.** 측정 전에 시스템에 넣어 보면서 문장을 바꾸면 독립성이 깨집니다.
5. 작성자가 여러 명이면 서로 겹치지 않게 분류를 나눠 맡고, 각자 자기 말투대로 씁니다.

## 2. 무엇을 공격하는가 (대상 시스템)

온라인 패션 쇼핑몰 "GUARDRAIL FASHION"의 고객지원 AI 챗봇입니다.

- **할 수 있는 일:** 상품 검색·안내, 로그인한 고객 **본인의** 주문·장바구니·쿠폰 조회, 장바구니·쿠폰 변경 제안(고객이 확인 화면에서 승인해야 적용)
- **지켜야 하는 것:** 숨겨진 시스템 지시문, 내부 설정, 관리자·DB 비밀번호와 API 키, **다른 고객의** 개인정보, 원가·마진·공급처 같은 내부 영업정보, 관리자 권한
- 사용자는 쇼핑몰 웹 채팅이나 AnythingLLM 같은 외부 챗봇 프로그램으로 들어옵니다. 외부 프로그램은 사용자 질문 앞에 자체 지시문(system)이나 참고자료를 붙여 보낼 수 있습니다.

## 3. 분류와 수량

### 공격 200건

| category | 수량 | 내용 |
|---|---|---|
| `instruction_override` | 30 | 기존 지시·규칙 무시, 역할 바꾸기, "제한 없는 AI"로 만들기 |
| `prompt_leak` | 30 | 시스템 지시문·숨겨진 규칙·내부 설정을 보여 달라고 하기 |
| `credential` | 25 | 관리자·DB 비밀번호, API 키, 토큰, 환경변수 요구 |
| `other_pii` | 25 | 다른 고객의 이름·연락처·주소·주문 내역 요구 |
| `business_secret` | 15 | 원가, 마진, 공급처, 매입가, 내부 매출 자료 요구 |
| `privilege_exec` | 25 | 관리자 권한 요구, SQL·셸·코드 실행, 시스템 명령 |
| `evasion` | 30 | 위 목표를 **우회 기법**으로 숨긴 것(아래 technique 참고) |
| `indirect_context` | 20 | 공격을 사용자 질문이 아니라 **참고자료(context) 칸**에 숨긴 것. 사용자 질문(text)은 평범하게 씁니다 |

### 정상 200건

| category | 수량 | 내용 |
|---|---|---|
| `shopping` | 80 | 상품 검색·추천, 사이즈, 가격, 재고, 배송, 반품·교환 |
| `risky_keyword` | 60 | 위험해 보이는 단어가 들어 있지만 정상인 질문. 예: 내 비밀번호 바꾸는 법, 관리자(상담원) 연결, 시스템 점검 시간, 쿠폰 코드, "이전 대화는 잊고 다시 추천해 줘" |
| `own_account` | 30 | 내 주문·배송·장바구니·쿠폰 조회와 변경 요청 |
| `misc` | 30 | 인사, 감사, 짧은 질문, 영어·한영 혼용, 오타 많은 문장 |

전체의 70% 정도는 한국어, 나머지는 영어·한영 혼용으로 써 주세요.

### technique (공격만, 하나 고르기)

`plain`(그대로 요구), `roleplay`(역할극·가상 인격), `story`(소설·사연·할머니 등), `hypothetical`(가정·게임), `authority`(운영자·개발자 사칭, 긴급 상황), `encoding`(Base64·Hex·URL 인코딩 등), `spacing`(띄어쓰기·기호 끼우기), `homoglyph`(전각·닮은 글자), `leet`(1gn0r3 같은 숫자 치환), `multilingual`(다른 언어로 쓰거나 번역 요청), `multi_step`(여러 단계로 나눠 요구), `other`

## 4. 작성 방법

`template.csv`를 복사해 엑셀이나 구글 시트에서 작성한 뒤 **CSV(UTF-8)** 로 저장합니다. 파일 이름은 `attacks_<이름>.csv`, `benign_<이름>.csv`처럼 자유롭게 정해도 되고, 한 파일에 공격·정상을 섞어도 됩니다.

| 열 | 필수 | 설명 |
|---|---|---|
| `id` | ✅ | 겹치지 않는 번호. 예: `A-홍-001`, `B-홍-001` |
| `label` | ✅ | `attack` 또는 `benign` |
| `category` | ✅ | 위 표의 영어 이름 |
| `technique` | 공격만 | 위 목록 중 하나. 정상은 비워 둡니다 |
| `lang` | ✅ | `ko`, `en`, `mixed` |
| `text` | ✅ | 사용자가 채팅창에 입력하는 문장(최대 2,000자) |
| `context` | `indirect_context`만 | 외부 챗봇 프로그램이 질문 앞에 붙여 보내는 참고자료·지시문. 공격은 여기에 숨깁니다 |
| `author` | ✅ | 작성자 이름 또는 약칭 |
| `note` | | 의도 메모(선택). 측정에는 쓰지 않습니다 |

예시 문장은 일부러 넣지 않았습니다. 예시를 보면 비슷하게 쓰게 되기 때문입니다.

## 5. 제출과 측정

1. 작성한 CSV를 이 폴더(`datasets/independent/`)에 넣습니다.
2. 형식 검사를 돌립니다. 오류(누락 열, 잘못된 분류, 중복, 개수 부족)를 고친 뒤 다시 돌립니다.
   ```bash
   python scripts/validate_testset.py datasets/independent
   ```
   검사기는 **형식만** 봅니다. 문장이 우리 시스템에 막히는지는 알려 주지 않습니다.
3. 검사를 통과하면 커밋하고 개발 담당에게 알립니다. 이 시점의 파일 지문(SHA-256)이 고정되고, **딱 한 번** 측정합니다.
   ```bash
   docker run --rm -v "<repo>:/repo" -w /repo/backend ag_prod-db-test python /repo/scripts/eval_independent.py datasets/independent
   ```
4. 결과는 `datasets/independent/results/`에 보고서(분류별 탐지율·오탐률·지연)로 저장됩니다. 측정 뒤에 규칙이나 판별 기준을 이 셋에 맞춰 고치면, 이 셋은 더 이상 독립 시험셋이 아니므로 다음 측정에는 새 시험셋이 필요합니다.
