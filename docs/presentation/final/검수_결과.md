### 2-2. "정규식 Fast-Path로 SLM 호출 절감" — 실제 설계와 반대

- **틀린 내용:**
  - "1ms/0.001초/0.01초 차단", "악성 요청 90% 이상 0.01초 사전 차단", "SLM 호출 85% 절감"
  - 해당 위치: 1·2·4·5·6·7·13·15·19쪽, 사례 1 전체, 예상 질문 3곳
- **사실:**
  - 정규식과 AI 판별은 **항상 둘 다 실행**하고, 어느 하나라도 막으면 차단합니다(OR). SLM 호출을 줄이는 구조가 **아닙니다**(D-25, D-36).
  - 측정된 지연:
    - 입력 판별 약 1.5~2초
    - 답변 생성 약 11초
    - 전체 P95 약 18.8초(보고서 PDF)
    - 쇼핑 응답 20~50초
  - "1ms", "90%", "85%"는 측정한 적이 없는 수치입니다.
- **수정:**
  - **사례 1을 다시 씁니다.**
    - 문제: CPU 추론(약 7 tok/s)이 느림
    - 해결: 호출 예산·타임아웃 재설계(D-15), 판별 타임아웃 45초, 처리 단계 칩을 실시간 표시(D-35)
  - 13쪽 "< 1 ms" 카드를 바꿉니다. 대안: "계층별 판정·처리 시간 기록 — 모든 이벤트에서 규칙/AI 판정과 각자 처리 시간을 남김(D-36)"

### 2-5. 구조·흐름 (5·6·7쪽)

- **"보안관제 대시보드 (Port 8501)":** 사용자는 `ops.example.internal`의 **443/8443(Nginx 경유)**으로 접속합니다. 8501은 내부 포트입니다.
- **"Step 3 도구 실행 검증: SQL Injection 방지·파라미터 화이트리스트":** 실제 동작은 두 갈래입니다.
  - **실행 가드:** 허용된 도구만 실행하고, 인자 형식을 검사하고, **본인 데이터만 조회**(`RULE_TOOL_OBJECT_ACCESS`)하게 합니다.
  - **도구 결과 검사:** 상품명 등 도구가 돌려준 데이터에 숨은 공격을 규칙+AI로 다시 검사합니다(간접 프롬프트 인젝션).
  - SQL 주입 방어는 파라미터 바인딩으로 하며, 가드레일 단계가 아닙니다.
- **"HITL 승인 모달 팝업":** 실제로는 **확인 화면 링크**입니다. 고객이 "이 내용으로 변경"을 누르고 5분 안에 승인해야 반영됩니다.
- **"4대 대응 액션 Allow/Block/Mask/Confirm":** 규칙 동작은 **block / mask / escape / observe**입니다. 확인(Confirm)은 변경 도구에 대한 실행 정책입니다.
- **"2계층: 경량 SLM 분류기":** 별도 분류 모델이 아니라 같은 qwen3:8b를 **판별용 프롬프트**로 부르는 LLM 판별기입니다.

### 2-7. 문제 해결 사례 (16쪽)

- **사례 5 (정규식 제안):**
  - 틀린 내용: "N-gram 토큰 추출", "2시간 → 3분 단축"
  - 사실:
    - qwen3:8b가 정규식을 **제안**합니다.
    - 서버가 4가지를 검사합니다: 문법·안전(ReDoS), 원문 일치, 정상 질문 90건 오탐 없음, 최근 정상 질문 오탐 없음.
    - 관리자가 **YES/NO**를 고르면 **관찰 모드**로 먼저 적용합니다.
    - 같은 질문이 반복되면 경보가 뜹니다(D-46, D-47).
  - 시간 단축 수치는 측정하지 않았으므로 뺍니다.
- **사례 6 (XSS):**
  - 틀린 내용: "unsafe_allow_html=True 사용 부주의로 실행", "html.escape() 전수 적용"
  - 사실: 처음부터 HTML 렌더링을 **쓰지 않았습니다**. 디자인 개편 때 CSS가 필요해지자, **고정 CSS 파일 1개만** `st.html` 한 곳에서 넣고 데이터는 절대 HTML로 넣지 않게 정했습니다(D-48). 사고가 난 것처럼 쓰면 안 됩니다.
- **빠진 사례 (지시서 목록에서 추가 권장):**
  - **D-42:** OFF인데도 공격이 안 통해 비교가 무의미했던 문제
  - **D-44/45:** 정상 장바구니 요청이 차단되던 문제
  - **D-36:** 대부분 AI에서 막혀 정규식이 안 보이던 문제
  - **10/14 Ollama 연결 끊김:** 준비 상태 점검으로 원인을 바로 찾은 사례
